# xvsXfs — формат файловой системы (версия 1.0)

«UniX version six, eXtended»: идеи xv6fs (суперблок → таблица inode →
каталоги-файлы), у которых сняты все ограничения, о которые мы спотыкались.
Формат описан в `kernel/xvsxfs/xvsx_format.h` (один заголовок и для ядра, и
для утилит). Все числа little-endian. Основа — xv6 (MIT); идеи extents,
каталогов и признаков совместимости — из публичных описаний ext2/ext4, без
кода ядра Linux.

| Параметр | xv6fs | xvsXfs |
|---|---|---|
| Блок | 512 Б | **4096 Б** |
| Inode | 64 Б | **512 Б** |
| Имя файла | 14 | **255** |
| Макс. файл | ~8 МБ | сотни ГБ (extents, 32-бит номера блоков → до 16 ТБ ФС) |
| Права, uid/gid | нет | **mode, uid, gid** (значения Linux) |
| Время | нет | **atime/mtime/ctime/crtime** с наносекундами |
| Симлинки | нет | **есть** |
| Малые файлы | отдельный блок | **inline в inode (≤ 256 Б)** |
| Контрольные суммы | нет | **crc32c** на суперблок, inode, блоки каталогов, узлы extents |
| Журнал | нет | **место и суперблок журнала (запись — следующий этап)** |

## Раскладка диска (блоки по 4 КБ)

```
блок 0                 зарезервирован (загрузочный код)
блок 1                 суперблок
блоки 2 .. 2+J-1       журнал (J = total/32, от 64 до 4096)
дальше                 битовая карта inode   (ceil(inodes / 32768) блоков)
                       битовая карта блоков  (ceil(blocks / 32768) блоков)
                       таблица inode         (inodes / 8 блоков)
data_start ..          данные (всё, что выделяется)
```
Бит = 1 — занято. Блоки метаданных (0 .. data_start-1) в карте блоков
помечены занятыми; «лишние» биты в конце карт тоже взведены. Inode
нумеруются с 1 (бит № = ino-1), корень — inode 1. Число inode по умолчанию
— один на 16 КБ.

## Суперблок (блок 1)

Магик `XVSXFS01`, версия, размер блока/inode, размеры и расположение всех
областей, UUID, метка, три набора флагов возможностей, состояние
(clean/dirty), счётчики свободного, время создания. **Последние 4 байта
блока — crc32c байтов 0..4091.**

Флаги: неизвестный `incompat`-бит — монтировать нельзя; неизвестный
`ro_compat` — только чтение; `compat` можно игнорировать. Бит
`INCOMPAT_RECOVER` ставится, когда журнал требует проигрывания.

## Inode (512 байт)

```
  0  mode (u16)   тип+права в значениях Linux (0100000 файл, 0040000 каталог, 0120000 симлинк ...)
  2  flags (u16)  1 = data содержит дерево extents, 2 = data содержит сами байты файла
  4  uid  8 gid  12 nlink  16 size (u64)  24 blocks (u64, блоки по 4К: данные + узлы дерева)
 32  atime mtime ctime crtime (i64, секунды)   64  те же наносекунды (4×u32)
 80  generation  84 rdev  88 csum (crc32c всего inode при csum=0)
 92  зарезервировано (нули)
128  data[256]   корень дерева extents ИЛИ inline-байты
384  xattr[128]  зарезервировано (в v1 — нули)
```

### Extents
`data` (и каждый узел-блок) начинается с 16-байтового заголовка (`magic
0x5845`, `entries`, `max`, `depth`), дальше записи по 12 байт.
* `depth = 0` — листья: `lblock` (первый логический блок), `len` (число
  блоков), `pblock` (первый физический).
* `depth > 0` — индекс: `lblock` (с чего начинается поддерево), `len` =
  номер блока-узла (там заголовок + записи + `crc32c` в байтах 4092..4095).

В inode помещается 20 записей, в узле-блоке 339. Читатель и fsck понимают
глубину до 4; мкфс сейчас пишет глубину 0 или 1 (до 6780 extents на файл).
Файл без дыр: логические блоки идут подряд (дыры читаются нулями, но
`mkfs` их не создаёт).

### Inline
Обычный файл или симлинк ≤ 256 байт хранится в `data`, `blocks = 0`.

## Каталоги
Каталог — обычный файл из блоков по 4 КБ, каждый блок самодостаточен.
Записи в стиле ext2: `ino (u32, 0 = свободно)`, `rec_len (u16, кратно 8)`,
`name_len (u8)`, `type (u8, значения Linux DT_*)`, имя без NUL. Записи
занимают байты 0..4079 ровно (последняя растягивается до конца); в
байтах 4080..4095 — хвост: `ino=0, rec_len=16, type=0xDE`, и crc32c байтов
0..4091 в последних четырёх. Первые две записи первого блока — «.» и «..».
Корень указывает «..» на себя. `nlink` каталога = 2 + число подкаталогов.
Поиск линейный (хэш-каталоги — возможное расширение).

## Журнал (резерв)
Первый блок журнала — суперблок журнала (`XVSXJRNL`, размер, голова,
номер транзакции, состояние clean, crc). Сейчас `mkfs` пишет чистый
журнал, а fsck проверяет, что он чист. План: журналирование метаданных
(данные пишутся до коммита, метаданные — через журнал), проигрывание при
монтировании.

## Инструменты (`tools/xvsx/`)
* `mkfs.xvsx IMAGE SIZE [--default-layout] [--mkdir /p] [--add /p=файл]
  [--symlink /p=цель] [--label L]` — создаёт и наполняет образ на хосте.
* `fsck.xvsx [-v] IMAGE` — только читает; код 0 чисто, 1 найдены проблемы,
  2 не удалось проверить. Проверяет суперблок и геометрию, журнал, каждый
  достижимый inode (сумма, тип, флаги, дерево extents и его суммы, диапазоны
  блоков, двойное владение, `size`/`blocks`), каждый блок каталога (хвост,
  цепочка записей, имена, «.» и «..», дубликаты, тип записи против inode),
  счётчики ссылок, «осиротевшие» inode, обе карты против найденного,
  счётчики свободного.
* `xvsx-dump IMAGE super|ls|cat|stat [путь]` — заглянуть внутрь образа.
* Тесты: `python3 tests/xvsx_test.py` (или `make xvsx-test`).
