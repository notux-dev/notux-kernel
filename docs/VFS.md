# Файловые системы notux: VFS и ext2

## Состояние

| Том | Устройство | Где | Режим |
|-----|-----------|-----|-------|
| xv6fs (корень) | AHCI диск 0 | `/` | чтение/запись, имена ≤14, без прав/времён/симлинков |
| ext2 | AHCI диск 1 | `/mnt` | чтение и запись (без журнала) |
| procfs | виртуальный | `/proc` | чтение |
| devfs | узлы T_DEV в xv6fs | `/dev` | — |

## Как устроено (лёгкий VFS)

Полноценного слоя с таблицей операций пока нет — слишком много кода syscalls
напрямую держит xv6 `struct inode` (~75 мест). Вместо рефакторинга всего разом:

* ext2-inode — это тот же `struct inode` из xv6-кэша, но с `dev == EXT2_DEV (1)`
  и дополнительными полями (`mode, uid, gid, atime/mtime/ctime, e2blk[15]`).
* Точки входа xv6fs (`ilock`, `iput`, `readi`, `writei`, `dirlookup`, `iupdate`,
  `xv6fs_truncate`, `xv6fs_create/remove/link/rename`) смотрят на `ip->dev`
  и для ext2 делегируют в `kernel/ext2/ext2.c` или возвращают `EROFS`.
* `namex()` переписан: имена до 255 байт, переход через точку монтирования
  (inode `/mnt` ↔ корень ext2, `..` из корня ext2 выходит наружу),
  следование симлинкам (глубина 8, `namei_nofollow` для lstat/readlink),
  `namei_enotdir` для ENOTDIR.
* Системные вызовы: `stat/lstat/fstatat` (реальные mode/uid/gid/времена),
  `getdents64` (переменная длина, `d_type`), `getcwd` (через точку монтирования),
  `readlink/readlinkat`.

## ext2 (kernel/ext2/ext2.c, ~900 строк)

* суперблок rev 0/1, размер блока 1–4 КиБ, размер inode из суперблока;
* прямые, одинарные, двойные и тройные косвенные блоки, дыры читаются нулями;
* каталоги (переменная длина записи, `d_type` из filetype);
* быстрые и медленные симлинки, узлы устройств (major/minor);
* кэш блоков 16 × 4 КиБ;
* **отклоняет** тома с неподдерживаемыми incompat-фичами (журнал на восстановление,
  extents, 64bit, ...). Образ делать так: `mke2fs -t ext2 -O ^has_journal -d DIR img SIZE`.

## Тест

`tools/mkext2test.sh` строит `ext2test.img` (длинные имена, каталог с 60 файлами,
файл 3 МБ через двойные косвенные блоки, дыра, симлинки: относительный,
абсолютный, на каталог, висячий, петля). `tests/musl_ext2.c` проверяет всё
через обычные Linux-вызовы; без второго диска он сам себя пропускает.
QEMU: второй диск `-drive id=disk1,file=ext2test.img,if=none,format=raw,snapshot=on
-device ide-hd,drive=disk1,bus=ahci0.1` (`snapshot=on` — ядро всё равно не пишет).

## Запись

Без журнала, write-through: каждое изменение метаданных сразу уходит на диск
(битмапы, счётчики групп и суперблока, inode, каталоги). Порядок «выделить → заполнить →
прилинковать» и «отлинковать → освободить» оставляет диск согласованным после каждого шага.

* блоки: аллокатор по группам (предпочитает группу inode), прямые/косвенные/двойные/тройные;
* файлы: `write` с ростом и дырами, `truncate` (рекурсивное освобождение косвенных блоков,
  обнуление хвоста), `O_APPEND`, `O_TRUNC`;
* каталоги: `create`, `mkdir`, `rmdir`, `unlink`, `link`, `symlink` (быстрые <60 байт и медленные),
  `rename` (замена цели, перенос каталога с правкой `..` и счётчиков, защита от переноса внутрь себя,
  `EXDEV` между томами);
* inode освобождается при последнем `close` удалённого файла (unlink открытого файла работает);
* `chmod/fchmod/fchmodat`, `chown/lchown/fchown/fchownat`, `utimes/futimesat/utimensat` пишут в inode
  (прав не проверяют: pseudo-root);
* права на создаваемые файлы берутся из `mode & ~022`.
* Проверка: после прогона тестов образ проверяется `e2fsck -fn` на хосте (должен быть чистым).

Ограничения: имя ≤255, файл <4 ГиБ, блоки 1–4 КиБ, нет резервных копий суперблока/GDT (их обновление не нужно
для e2fsck -n), нет `mknod`/fifo, права не проверяются, `fsync` — пустышка (write-through).

## Следующие шаги

1. `mknod`/fifo, `fallocate`, сброс/синхронизация, права и токены в `lookup`.
2. Настоящий VFS (таблица `fsops`, смонтированные тома в таблице, `lookup` как место для
   проверки токенов — «нет токена ⇒ ENOENT»).
3. Корень на ext2, xv6fs остаётся запасным.
4. ext4 только для чтения (extents), потом `dir_index`/`metadata_csum`.

## Корень на ext2

Диск 0 может быть ext2 (определяется по сигнатуре при старте). Тогда `/` — корень ext2 (inode 2), второй диск не используется,
`/mnt`-монтирования и bind `/lib` отсутствуют, а `/dev`-узлы — обычные символьные inodes (major/minor Linux, `debugfs mknod`).
Иначе — прежний режим: корень xv6fs, ext2 с диска 1 на `/mnt`.
