# Лестница совместимости notux: 50 программ

Идея: каждая ступень — реальная, неизменённая Linux-программа (статически, musl),
которая заставляет ядро получить ровно несколько новых возможностей. Ступень
считается пройденной, когда проходит её «критерий». Всё проверяется в QEMU.

Как работать со ступенью:
1. Собрать статически против `musl/` (рецепт — `tools/ladder/NN-имя.sh`).
2. Запустить с `make iso TRACE=1`: в serial видны `ENOSYS nr=…` и последовательность
   вызовов — это и есть список недостающего.
3. Реализовать недостающее, добавить тест в `tests/`, пройти критерий.
4. Отметить ступень ✅ ниже.

Сложность и требования указаны на момент написания: «нужно» — чего в ядре ещё нет.

## Что открывает каждый ярус

- A–B: свой шелл и терминал (дальше можно работать внутри notux).
- C–D: нормальный набор утилит.
- E–F: «похоже на настоящий Linux»: `fastfetch`, `vim`, python.
- G: самохостинг (tcc → make → gcc). Когда собираешь tcc внутри notux, система доказала, что она больше не игрушка.
- H–I: дистрибутив: init, пакеты, сеть, git.

План на будущее по порядку работ — `docs/ROADMAP.md`.
- J: динамика (общая планка для готовых дистрибутивов вроде Alpine) и графика.

## Служебные «ступени» без своей программы

Прогонять после каждого яруса: musl libc-test (подмножество), LTP (выбранные syscalls),
busybox testsuite. Они находят баги в вызовах, которые обычные программы
не трогают.
